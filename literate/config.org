* 使用说明

本文件是 ~/.config/doom/ 下 Doom Emacs 私人配置的**唯一真源**，用 Org
babel 文学化方式组织：

- 顶层的 ~config.el~ 只是引导文件，启动时把本文件 tangle 成
  ~literate/config.el~ 并加载（只有本文件比 ~.el~ 新时才重新 tangle）。
- 下面的每一个 ~#+begin_src emacs-lisp~ 代码块都是一段真实生效的配置，
  修改后重启 Emacs（或执行 ~M-x org-babel-tangle~ / ~org-babel-load-file~）生效。
- 普通文字段落只作说明，不会被加载。

迁移自原 ~config.el~（备份见 ~config.el.bak-20260902~），要点：

- 原代码开头指向不存在的 ~/.doom.d/lisp~ 的死路径已修正为真实的
  ~doom-user-dir/lisp~（即 ~/.config/doom/lisp~）；
- 原模板注释里被注释掉的示例（全屏、字体等）已移入对应章节的说明文字，
  不再出现在生成的 ~.el~ 里；
- 末尾 ~(load! "lisp/dsh")~ 因生成文件位于 ~literate/~ 子目录、相对基准
  变化，改为显式传入目录。

* PATH 同步（exec-path-from-shell）

macOS 上从 Dock/Spotlight 启动的 GUI Emacs 不会继承交互 shell 的
~PATH~——只有从终端里 ~emacs~ 启动才凑巧能用。~claude-code.el~、cch、
dsh、gptel 这些都要 ~executable-find~ 或直接 shell 出去找 ~claude~ /
~dsh~ 之类的命令，PATH 不对就会报"program not found in PATH"（哪怕
终端里 ~which claude~ 明明有）。用 [[https://github.com/purcell/exec-path-from-shell][exec-path-from-shell]] 在启动时把交互 shell
的 ~PATH~ 抄一份过来，一劳永逸。

#+begin_src emacs-lisp
(when (memq window-system '(mac ns x))
  (require 'exec-path-from-shell)
  (setq exec-path-from-shell-variables '("PATH"))
  (exec-path-from-shell-initialize))
#+end_src

** macOS 菜单栏番茄钟联动

给 [[https://github.com][macOS 菜单栏番茄钟]]（原生 SwiftUI app）提供的桥接函数，通过
~emacsclient --eval~ 调用。每个函数返回一个 JSON 字符串（用 ~json-encode~），
方便 Swift 那边直接解析，不用去啃 elisp 的 prin1 转义。

计时权威在 Mac app 一侧（它自己有倒计时逻辑），Emacs 这边只在专注段
**开始**和**结束**这两个时刻各被调用一次（clock-in / clock-out），中途
完全不通信、不用 org-pomodoro 自己的计时器——避免两边计时器各转各的、
互相打架。

- ~my/pomodoro-bridge-list-todos~ —— 列出 org-agenda-files 里所有未完成的
  TODO，带 file/pos/heading/path，供 Mac app 弹窗选择。
- ~my/pomodoro-bridge-clock-in~ —— 按 Mac app 传回的 file/pos/heading 在
  对应标题下 clock-in（只记账，不启动 org-pomodoro 自己的计时器）。
- ~my/pomodoro-bridge-clock-out~ —— 结束当前 clock（Mac app 倒计时走完，
  或用户在 Mac app 里点"终止"时调用一次）。
- ~my/pomodoro-bridge-stats~ —— 按标题统计今天/近 7 天的 clock 时长，
  给 Mac app 的统计面板用，直接复用 org-clock-sum，不在 Swift 里重新解析
  LOGBOOK。

#+begin_src emacs-lisp
(after! org
  (require 'json)

  (defun my/pomodoro-bridge--todo-p ()
    (let ((state (org-get-todo-state)))
      (and state (member state org-not-done-keywords))))

  (defun my/pomodoro-bridge-list-todos ()
    "JSON 数组：org-agenda-files 里所有未完成 TODO 的 file/pos/heading/path。"
    (let (entries)
      (dolist (file (org-agenda-files))
        (when (file-exists-p file)
          (with-current-buffer (find-file-noselect file)
            (org-with-wide-buffer
             (org-map-entries
              (lambda ()
                (when (my/pomodoro-bridge--todo-p)
                  (push (list (cons "file" file)
                              (cons "pos" (point))
                              (cons "heading" (org-get-heading t t t t))
                              (cons "path" (mapconcat #'identity
                                                       (org-get-outline-path)
                                                       " > ")))
                        entries)))
              nil 'file)))))
      (json-encode (nreverse entries))))

  (defun my/pomodoro-bridge-clock-in (file pos heading)
    "在 FILE:POS（校验标题文本等于 HEADING）处 clock-in。只记账，不涉及
org-pomodoro 自己的计时器——Mac app 才是计时权威。"
    (condition-case err
        (progn
          (with-current-buffer (find-file-noselect file)
            (widen)
            (goto-char (min (max pos (point-min)) (point-max)))
            (beginning-of-line)
            (unless (and (looking-at org-complex-heading-regexp)
                         (equal (org-get-heading t t t t) heading))
              (goto-char (point-min))
              (unless (re-search-forward
                       (concat "^\\*+[ \t]+.*" (regexp-quote heading)) nil t)
                (error "找不到标题：%s" heading))
              (beginning-of-line))
            (when (org-clocking-p) (org-clock-out))
            (org-clock-in)
            (save-buffer))
          (json-encode (list (cons "ok" t))))
      (error (json-encode (list (cons "ok" :json-false)
                                 (cons "error" (error-message-string err)))))))

  (defun my/pomodoro-bridge-clock-out ()
    "结束当前 clock（Mac app 那边的专注段走完，或用户点了终止）。"
    (condition-case err
        (let ((buf (and (org-clocking-p) (marker-buffer org-clock-marker))))
          (when (org-clocking-p) (org-clock-out))
          (when buf (with-current-buffer buf (save-buffer)))
          (json-encode (list (cons "ok" t))))
      (error (json-encode (list (cons "ok" :json-false)
                                 (cons "error" (error-message-string err)))))))

  (defun my/pomodoro-bridge-stats ()
    "按标题统计今天/近 7 天的 clock 分钟数，JSON 数组。"
    (let* ((today-start (apply #'encode-time 0 0 0 (nthcdr 3 (decode-time))))
           (week-start (time-subtract today-start (* 6 86400)))
           (now (current-time))
           results)
      (dolist (file (org-agenda-files))
        (when (file-exists-p file)
          (with-current-buffer (find-file-noselect file)
            (org-with-wide-buffer
             (org-clock-sum today-start now nil :clock-today)
             (org-clock-sum week-start now nil :clock-week)
             (org-map-entries
              (lambda ()
                (when (my/pomodoro-bridge--todo-p)
                  (push (list (cons "heading" (org-get-heading t t t t))
                              (cons "path" (mapconcat #'identity
                                                       (org-get-outline-path)
                                                       " > "))
                              (cons "todayMinutes"
                                    (or (get-text-property (point) :clock-today) 0))
                              (cons "weekMinutes"
                                    (or (get-text-property (point) :clock-week) 0)))
                        results)))
              nil 'file)))))
      (json-encode (nreverse results)))))
#+end_src

* Org：字体与 faces（Ricing Org Mode）

Tufte 风格：正文用旧式衬线（教程用 ET Book / ~EtBembo~，未安装则自动回退
Iowan Old Style），标题用近黑墨色、以字号与斜体区分层级；代码、表格用等宽
字。正文衬线由 ~variable-pitch-mode~ 生效（见 hook 一节）。字高为相对默认

#+begin_src emacs-lisp
(require 'cl-lib)

;; 字体选择：优先教程字体，未安装则回退 macOS 自带字体
(defun my/first-available-font (candidates fallback)
  "Return the first installed font family in CANDIDATES, else FALLBACK."
  (or (cl-loop for family in candidates
               if (member family (font-family-list))
               return family)
      fallback))

(defconst my/org-serif-font
  (my/first-available-font '("ETBookOT" "EtBembo" "Iowan Old Style" "Charter" "Georgia")
                           "Georgia"))

* gptel（多轮聊天 + 选区改写）集成

上面 claude-code/dsh/cch 三个都是"发一句、等一个结果"的模式（要么是交互式
终端会话，要么是单次问答）。[[https://github.com/karthink/gptel][gptel]] 补的是另一种形态：一个真正的多轮对话
buffer（org-mode 写的，问答历史就是文档本身，可以回头编辑、折叠、另存），
外加 ~gptel-rewrite~ 直接对选中区域做"改写并预览 diff"。

后端配了两个，跟 Claude/DeepSeek 都能聊，随时用 ~gptel-menu~（~C-c g m~）切换：
- Claude（Anthropic 原生 API，不是 claude CLI）
- DeepSeek（OpenAI 兼容接口）

*密钥不写在配置里*，走 auth-source（~~/.authinfo.gpg~）读取。首次使用前
用 GPG 加密创建这个文件，内容两行：

#+begin_example
machine api.anthropic.com login gptel password sk-ant-你的key
machine api.deepseek.com login gptel password sk-你的key
#+end_example

（没有 DeepSeek key 也没关系，只是 ~gptel-menu~ 里切不过去那个后端而已，
Claude 后端不受影响。）

快捷键：
- ~C-c g g~ / ~SPC g g~ — 打开/切到 gptel 聊天 buffer
- ~C-c g s~ / ~SPC g s~ — 发送当前 buffer（续聊）
- ~C-c g m~ / ~SPC g m~ — 命令菜单（切后端/切模型/切系统提示等）
- ~C-c g r~ — 选中区域，用模型改写，改写结果先以 diff 形式预览再决定是否应用

(use-package! gptel

  :init

          :stream t

  (setq gptel-model 'claude-sonnet-5)

  (gptel-make-openai "DeepSeek"
    :host "api.deepseek.com"
    :endpoint "/chat/completions"
    :stream t
    :key (lambda ()
           (auth-source-pick-first-password
            :host "api.deepseek.com" :user "gptel"))
    :models '(deepseek-chat deepseek-reasoner))
  :bind (("C-c g g" . gptel)
         ("C-c g s" . gptel-send)
         ("C-c g m" . gptel-menu)
         ("C-c g r" . gptel-rewrite)))

(when (fboundp 'map!)
  (map! :leader
        :desc "gptel: 打开聊天窗口" "g g" #'gptel

        :desc "gptel: 命令菜单"     "g m" #'gptel-menu

** 知网源刷新会重复的问题

知网 =rss.cnki.net= 的每条 =<item>= 都没有 =<guid>=，=<link>= 里还带一段
每次请求都重新生成的追踪 token（形如
=kcms2/article/abstract?v=随机串&...=）。elfeed 给条目算 id 时优先用
guid，没有就退而用 link——同一篇论文，这次刷新和下次刷新链接里的 token
不一样，id 也就跟着变，于是被当成两条不同的新文章重复收进来（标题、
内容其实完全一样）。JASIST 等有正规 guid/DOI 链接的源不受影响。

解法是把知网这几个源的 id 换成「命名空间 + 标题」，标题没变就还是同一
条目，elfeed 会走合并（=elfeed-entry-merge=）而不是新建，已读/星标状态
也不会丢：

#+begin_src emacs-lisp
(after! elfeed
  (defun +rss-cnki-stabilize-id (type _item entry)
    "稳定知网 RSS 条目的 id，避免链接里的随机追踪 token 导致刷新出重复文章。"
    (when (and (eq type :rss)
               (string-match-p "rss\\.cnki\\.net" (elfeed-entry-feed-id entry)))
      (setf (elfeed-entry-id entry)
            (cons (car (elfeed-entry-id entry))
                  (elfeed-entry-title entry)))))
  (add-hook 'elfeed-new-entry-parse-hook #'+rss-cnki-stabilize-id))
#+end_src

（2026-09-05 已经手动清过一次数据库把之前的重复条目清空了，不需要再跑
一遍。以后再遇到类似"某个源没有稳定 guid/链接会变"的情况，参照上面
这段 hook 的写法处理，而不是清空整个数据库——清库是一次性手动操作，
不要把它写成会被 tangle 进 config.el、每次启动 Emacs 都执行的代码块。）

** 每天自动检测订阅源是否失效

2026-09-05 加了一个独立于 Emacs 的每日健康检查（不是 elisp，是普通脚本 +
macOS launchd，即使 Emacs 没开着也会跑）：

- 脚本：[[file:~/.config/doom/bin/check-rss-feeds.py][bin/check-rss-feeds.py]] ——
  读 =elfeed.org= 里的订阅列表（单一数据源，不用再维护第二份），对每个源
  发请求，检查 HTTP 状态、是不是合法 RSS/Atom、有没有文章条目
- 定时器：=~/Library/LaunchAgents/com.geo.rss-feed-check.plist=，每天
  9:00 触发一次
- 有源失效时弹 macOS 桌面通知；全部正常则不打扰
- 每次运行结果覆盖写在 =bin/rss-check.log=（launchd 自身的 stdout/stderr
  在 =bin/rss-check-launchd.log=），只保留最近一次，不会一直变大

需要临时关掉：=launchctl bootout gui/$(id -u)/com.geo.rss-feed-check=
需要手动跑一次：=launchctl kickstart gui/$(id -u)/com.geo.rss-feed-check=
彻底卸载：上面 bootout 之后把 plist 和 =bin/= 下这两个脚本/日志文件删掉即可。

新加的订阅不用额外配置——脚本每次都是现读 =elfeed.org=，加完直接下一次
就会被测到。失效之后**不会自动找替换源顶上**——找替换源需要上网搜索、
验证候选链接，这类判断交给固定脚本做风险更大（乱猜的候选源可能是错的，
写错了反而更麻烦），2026-09-05 明确决定保持"检测自动、修复找 Claude
手动处理"这个分工，不做无人值守的自动修复。
